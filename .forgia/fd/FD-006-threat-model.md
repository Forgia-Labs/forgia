## 4. Recommendations for SDDs

1. **SDD-001**: Add request size limit to `StdioTransport.ReadRequest()` — reject JSON-RPC requests larger than 10MB to prevent memory exhaustion. Log every `tools/call` invocation (tool name + timestamp, NOT parameters) for audit trail.
2. **SDD-002**: Validate provider command paths before spawning — reject commands containing shell metacharacters (`; | & $ \``). Use `exec.LookPath` to resolve command to absolute path. Log resolved path at startup.
3. **SDD-003**: Document that `VaultReader` is intentionally narrow — 4 methods only. If widened later, re-assess what data composite skills can access.
4. **SDD-004**: `forgia_search_code` PostProcess MUST apply `guardrails.CheckFilePaths()` to filter results matching `[read]` deny patterns. Add test with fixture containing `.env` and `*.pem` paths — verify they are stripped from results. `forgia_arch_init` must merge with existing architecture files, not overwrite — check file existence before writing.
5. **SDD-005**: `forgia_security_scan` must NOT return actual secret values found in code — only file paths and pattern names. Apply the same `ScanForSecrets` approach from `guardrails.go` (line 256-280): report location without content.
6. **SDD-006**: Cache MCP reachability result for the duration of a single slash command invocation — don't re-check on every step. Document that MCP communication is local-only (stdio, same user).
7. **SDD-007**: Add integration test: register a mock tool that returns results containing deny.toml-matched paths → verify `forgia_search_code` strips them. Add test: send oversized JSON-RPC request → verify server rejects gracefully.

## 5. Guardrails Additions

Proposed additions to `.forgia/guardrails/deny.toml`:

```toml
[execute]
# Prevent provider config from spawning arbitrary shells
"sh -c*"
"bash -c*"
"/bin/sh*"
"/bin/bash*"
```

These patterns prevent `[mcp.providers.*]` command fields from being used for shell command injection. If a provider needs a shell wrapper, it should be an explicit script file, not an inline shell command.

No additional `[read]` or `[write]` patterns needed — existing coverage is sufficient for the MCP server use case.
